# 显示内容

状态栏提供 26 个可配置字段。在[交互预览](/preview)中，可以选择显示哪些字段、调整顺序并设置颜色。操作步骤见[配置状态栏](./configuration.md)。

右侧的 `v0.1.1` 等文字表示插件版本。`codex_version` 字段表示 Codex CLI 版本。

## 全部 26 个字段

| 字段 | 含义 |
| --- | --- |
| `label` | 自定义标签，默认为 `CODEX` |
| `model` | 当前模型 |
| `reasoning` | 推理强度，例如 `high` |
| `activity` | Review、Plan 或 Goal 状态 |
| `provider` | 模型服务商 |
| `personality` | 会话的 personality 设置 |
| `service_tier` | 服务等级 |
| `cwd` | 当前工作目录 |
| `project` | Git 根目录名，非 Git 目录省略 |
| `git` | 当前 Git 分支 |
| `permissions` | 沙箱权限摘要 |
| `approval` | 审批策略 |
| `context` | 剩余上下文比例或进度条 |
| `context_used` | 已用上下文比例 |
| `context_window` | 上下文容量，例如 `272K window` |
| `used_tokens` | 累计输入和输出，例如 `↑10M ↓204K` |
| `cache_rate` | 缓存输入占总输入的比例 |
| `cost` | 估算费用，例如 `Cost ~$22.48` |
| `input_tokens` | 累计输入，包含缓存 |
| `cached_tokens` | 累计缓存输入 |
| `output_tokens` | 累计输出，包含推理输出 |
| `reasoning_tokens` | 累计推理输出 |
| `thread_id` | 会话 ID 的前八位 |
| `task_progress` | 预览中的任务进度；实际会话不会自动提供此字段 |
| `codex_version` | Codex CLI 版本 |
| `icon` | 项目图标，固定在右侧插件版本号之前 |

字段依赖会话中可用的数据。PR、调用额度和 Enterprise credits 等信息不在本扩展的显示范围内。

## 特殊状态

`activity` 显示 `REVIEW`、`PLAN` 或 Goal 状态。多个状态同时存在时，优先显示 `REVIEW`，其次是 `PLAN`，最后是 Goal。

Goal 状态包括进行中、暂停、阻塞、用量限制、预算限制和完成。标签文字可以通过 `activity.labels` 修改，见[配置选项](../reference/settings.md#特殊状态文字)。

## 窗口宽度与行数

状态栏根据可用列数调整内容：

| 列数 | 显示方式 |
| ---: | --- |
| 少于 60 | 保留标签、模型、活动状态、上下文和右侧标识 |
| 60–89 | 隐藏高级元数据和 Token 明细 |
| 90–119 | 上下文使用八格进度条 |
| 120 及以上 | 上下文使用十格进度条，显示更多可用字段 |

空间仍不足时，会继续隐藏次要字段。右侧优先显示插件版本号，其他内容按剩余宽度截取。

两行布局需要设置 `bottom_pane.rows = 2`。此时上下文、Token、缓存率和费用位于第二行，其他字段位于第一行。

## Token 与费用

`used_tokens` 显示当前会话的累计输入和输出：

```text
↑10M ↓204K
```

输入包含缓存输入，输出包含推理输出。因此，缓存输入和推理输出不能再分别加到对应总数上。

`cache_rate` 的计算方式为：

```text
缓存率 = 缓存输入 / 总输入 × 100%
```

没有输入数据时显示 `Cache —`；输入非零但没有缓存命中时显示 `Cache 0%`。

`cost` 按每次请求使用的模型估算费用，再累计整段会话的结果：

```text
单次费用 = ((输入 - 缓存输入) × 输入单价
      + 缓存输入 × 缓存单价
      + 输出 × 输出单价) / 1,000,000

会话费用 = 各次请求费用之和
```

单价单位为美元/百万 Token。例如，先使用 Sol 再切换 Astra，先前的用量仍使用 Sol 单价，之后的用量使用 Astra 单价。切换模型本身不会改变累计费用。

恢复已有线程时，会从会话记录重建费用。历史读取尚未完成、记录不完整，或某段用量缺少模型信息或价格时，显示 `Cost —`。费用保留两位小数；大于零但不足一美分时显示 `Cost <$0.01`。

该数值不代表实际账单，也不包括长上下文、加速、缓存写入及工具费用。估算使用各模型当前配置的单价；修改某个模型的价格会更新该模型对应的历史费用。自定义单价见[费用与自定义模型价格](./configuration.md#费用与自定义模型价格)。

数字使用 `K/M/B/T` 缩写，例如 `1.23K`、`533K` 和 `4.2M`。会话已有用量数据但输入或输出为零时，对应显示 `0`。

## 上下文剩余比例

上下文使用最近一次请求的用量，Token 字段使用整个会话的累计用量。

剩余比例按 Codex 的 12,000 Token 基准计算：

```text
有效容量 = 上下文容量 - 12,000
已用容量 = max(最近一次总用量 - 12,000, 0)
剩余比例 = round((有效容量 - 已用容量) / 有效容量 × 100%)
```

结果限制在 0–100%。上下文容量未知时，显示当前上下文 Token 数；用量也不可用时显示等待状态。上下文容量不大于 12,000 时显示 0%。

## 等待状态

| 显示 | 含义 |
| --- | --- |
| `waiting` | 还未找到当前窗格对应的会话记录 |
| `tokens: waiting` | 已找到会话，但还未收到 Token 用量 |

新会话通常需要先发送一条消息。如果状态持续不变，见[等待状态排查](../troubleshooting/common-issues.md#持续显示-waiting)。

## 刷新频率

默认每秒检查进程和会话新增内容，每五秒更新 Git 信息。实际刷新还受 WezTerm 的 `status_update_interval` 设置影响。
